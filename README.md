# CyberCheck

Единый локальный инструмент для проверки сайта: TCP-порты, DNS, поиск поддоменов, сведения о веб-сайте и TLS, инфраструктурный OSINT. Веб-панель на русском языке, CLI, история в SQLite и экспорт в HTML / JSON / CSV.

## Запуск

Нужен Python 3.11 или новее. Выполняйте команды в папке проекта.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m cybercheck serve
```

Если библиотеки уже установлены:

```powershell
python -m cybercheck serve
```

Откройте **http://127.0.0.1:8765**. Введите домен, HTTP(S)-адрес или отдельный IP. Выберите модули и профиль, нажмите «Запустить проверку». Команда `python -m cybercheck serve --port 9000` меняет порт панели. `start.ps1` запускает панель из папки проекта; остановка — Ctrl+C в терминале, где работает сервер.

На Linux/macOS создайте окружение через `python3 -m venv .venv` и используйте `.venv/bin/python` вместо `.\.venv\Scripts\python.exe`.

Адрес Git-репозитория, например `https://github.com/yerasnetwork/osint_checker.git`, является адресом исходников, а не целью сканирования. Сканер отклоняет такие цели.

## Что входит

| Модуль | Результаты |
| --- | --- |
| Порты | TCP connect, IP/порт, открыто/закрыто/нет ответа/ошибка, время соединения, добровольно отправленные баннеры |
| DNS | IP через системный DNS; A, AAAA, CNAME, MX, NS, TXT, SOA, CAA через DNS-over-HTTPS |
| Поддомены | Публичные сертификаты через crt.sh, небольшой встроенный список имён, DNS-проверка, отметки wildcard и исторических имён |
| Веб | HTTP-статус, редиректы, заголовок страницы, HTTP-заголовки, имена/атрибуты cookies, признаки технологий, robots.txt, sitemap.xml |
| TLS | Проверка доверия сертификату, издатель, сроки, SAN, отпечаток SHA-256, согласованные TLS и шифр |
| OSINT | Доменные и IP-сведения RDAP, события регистрации, регистратор при наличии, сеть/провайдер, ASN и префикс через Team Cymru DNS |

Результаты выводятся в порядке: **открытые порты → поддомены → DNS → веб → TLS → OSINT**. Вкладки позволяют смотреть все состояния портов с поиском и пагинацией, сведения по модулям, замечания и журнал. Каждый запуск сохраняется; ошибки источников сохраняются вместе с результатами. Остановка сохраняет уже проверенные порты и имена. Прерванные при перезапуске сервера проверки отмечаются в истории.

## Настройки и границы проверки

- Быстрый профиль содержит 25 TCP-портов; стандартный — расширенный список популярных портов. Полный — 1–65535. Можно задать собственный список, например `22,80,443,8000-8100`. Порт, явно указанный в URL, добавляется к профилю.
- По умолчанию проверяется один IP цели, с приоритетом IPv4. В настройках можно выбрать до четырёх IP. Все найденные IP и реально проверенные адреса сохраняются в отчёте. UDP-проверок нет.
- Портам сначала присваивается предположительное название по номеру. Nmap, если установлен и выбран в настройках, отдельно определяет службы на уже открытых портах. Используются TCP connect и лёгкое определение версии, без NSE-скриптов. Nmap необязателен; при его отсутствии обычный сканер работает.
- Таймаут означает «нет ответа», а не «закрыт». Сетевые ошибки показываются отдельно.
- Портовые проверки относятся к IP исходной цели. Найденные поддомены автоматически не сканируются по портам. Для них можно отдельно включить HTTPS-проверку. HTTP-редиректы следуют только к исходному имени или его поддоменам; внешние переходы записываются и останавливаются.
- Публичные источники — Cloudflare/Google DNS-over-HTTPS, crt.sh, RDAP и Team Cymru через DNS. Их отключение оставляет системный DNS и проверки самой цели. Этот режим не означает отсутствие сетевых запросов.
- Для локальных IP публичные IP-запросы пропускаются. Цели CIDR не принимаются. Используйте активные проверки для своих систем или согласованных целей.
- Ошибка доверия TLS сохраняется. Сертификат можно повторно получить без проверки доверия **только для чтения метаданных**; обычные HTTP-запросы продолжают проверять TLS.
- Полнота списка поддоменов не гарантируется. CT может содержать старые имена; wildcard DNS может отвечать для несуществующих имён. IP за CDN может принадлежать CDN. Признак технологии не подтверждает её версию или уязвимость.
- Ограничения скорости и параллелизма действуют на каждый запуск; одновременно допускаются две проверки. Ответы внешних сервисов ограничены по размеру; модули имеют таймауты.

Панель слушает только `127.0.0.1`. Проверяет Host и блокирует запуск с чужого Origin. Интерфейс не использует CDN и внешние шрифты. Данные целей отображаются как текст, HTML-отчёты экранируют содержимое, CSV защищён от формул. Значения cookies не включаются в отчёт.

## CLI

```powershell
# Полная стандартная проверка своей цели
python -m cybercheck scan https://your-domain.example --profile standard

# Указанные порты; без публичных сторонних источников
python -m cybercheck scan http://127.0.0.1:8765 --ports 8765,8766 --offline

# Только DNS, поддомены и OSINT
python -m cybercheck scan your-domain.example --modules dns,subdomains,osint

# Версии служб через отдельно установленный Nmap
python -m cybercheck scan your-domain.example --ports 22,80,443 --nmap

# Указать папку отчётов
python -m cybercheck scan your-domain.example --output reports/my-check
```

Все CLI-проверки сохраняются в общей истории. По завершении создаются `report.json`, `report.html`, `report.csv` в папке `reports/<id>` или в указанной через `--output`. База истории находится в `data/cybercheck.sqlite3` относительно текущей рабочей папки. Папки `data` и `reports` исключены из Git.

## API

- `GET /api/health`, `GET /api/info` — состояние и доступные профили.
- `POST /api/scans` — запуск; тело соответствует настройкам `ScanConfig`.
- `GET /api/scans` — история.
- `GET /api/scans/{id}` — полный результат; `?compact=true` — небольшой ответ для обновления панели.
- `GET /api/scans/{id}/ports?state=open&offset=0&limit=100&search=443` — фильтрация портов.
- `POST /api/scans/{id}/cancel` — остановка.
- `GET /api/scans/{id}/export?format=html` — `html`, `json` или `csv`.

Описание API: http://127.0.0.1:8765/docs.

## Проверка проекта

```powershell
python -m unittest discover -v
python -m compileall -q cybercheck
node --check cybercheck/static/app.js
```

Тесты используют локальные TCP/TLS-сервисы и ответы публичных источников, воспроизведённые через HTTPX MockTransport. Для тестов не нужен интернет, API-ключи или установленный Nmap. Node нужен только для проверки синтаксиса фронтенда, для работы приложения он не требуется.

## Структура

```text
cybercheck/
  models.py       цели, настройки, профили портов
  network.py      ограничение скорости, DNS, HTTP и границы редиректов
  modules.py      порты, DNS, поддомены, веб, TLS, OSINT
  runner.py       задачи, прогресс, отмена
  storage.py      SQLite и история
  reports.py      HTML / JSON / CSV
  server.py       FastAPI и локальная панель
  cli.py          команды serve и scan
  static/         интерфейс без внешних зависимостей
tests/            автоматические проверки
```
